## 一、安装

StoryForge 是一个**本地运行的单机程序**，需要先准备两样东西：Python 与 FFmpeg。

### 1.1 安装 Python（必需）

1. 打开官网 <https://www.python.org/downloads/>，下载 **Python 3.13**（3.10 及以上均可）。
2. 安装时**务必勾选** 页面底部的 **「Add Python to PATH」**（加入环境变量），否则后面的启动脚本找不到 Python。
3. 安装完成后，打开「命令提示符」（Win + R 输入 `cmd`），输入：

   ```bat
   python --version
   ```

   若显示 `Python 3.13.x` 即安装成功。

### 1.2 安装 FFmpeg（必需）

FFmpeg 用于生成占位视频与拼接成片，没有它就无法出片。

1. 打开 <https://www.gyan.dev/ffmpeg/builds/>，下载 **ffmpeg-release-essentials.zip**。
2. 解压到任意目录，例如 `C:\ffmpeg`（解压后应能看到 `C:\ffmpeg\bin\ffmpeg.exe`）。
3. 把 `C:\ffmpeg\bin` 加入系统环境变量 **PATH**：
   - 「此电脑」右键 →「属性」→「高级系统设置」→「环境变量」；
   - 在「系统变量」中找到 `Path`，双击 →「新建」→ 填入 `C:\ffmpeg\bin` → 一路确定。
4. **重新打开**命令提示符，输入：

   ```bat
   ffmpeg -version
   ```

   能打印出版本信息即配置成功。

### 1.3 获取项目

把整个 `storyforge` 文件夹放到电脑上任意位置（建议非中文、无空格的路径，例如 `E:\ai\storyforge`）。

## 二、启动

1. 进入 `storyforge` 文件夹，**双击 `start.bat`**。
2. 脚本会自动按顺序完成 4 件事，每一步都有中文提示：

   | 步骤 | 动作 |
   | --- | --- |
   | [1/4] | 查找 Python |
   | [2/4] | 创建 / 复用项目内虚拟环境 `.venv` |
   | [3/4] | 安装依赖（首次约 1–3 分钟） |
   | [4/4] | 检测 FFmpeg |

3. 之后服务启动，**浏览器会自动打开**页面（地址形如 `http://127.0.0.1:8000`）。
   页面顶部会显示实际访问地址——若 8000 端口被占用，程序会自动换成 8001、8002……

4. **关闭那个黑色命令行窗口即停止服务**。下次使用再次双击 `start.bat` 即可（依赖已装好，启动很快）。

> 小提示：`start.bat` 窗口不要关闭，它是服务的「发动机」。

## 三、配置

打开页面后，第一件事是「① 配置区」。

### 3.1 选择 LLM（大脑）

| 模式 | 适用人群 | 需要填写 |
| --- | --- | --- |
| **本地 Ollama（零成本）** | 已安装 Ollama 的用户（推荐新手） | 无需 API Key，只需模型名与 Base URL |
| **OpenAI 兼容接口** | 已购买 DeepSeek / 通义 / Kimi / GLM 等 API 的用户 | Base URL、API Key、模型名 |

**使用本地 Ollama 的方法**（零成本）：

1. 安装 Ollama：<https://ollama.com/download>。
2. 打开命令提示符，拉取一个中文能力较好的模型：

   ```bat
   ollama pull qwen2.5:14b
   ```

3. 确认 Ollama 正在运行（`ollama serve`，通常安装后会自动后台运行）。
4. 回到页面，选择「本地 Ollama」，点「刷新」按钮可自动列出本地模型；选一个模型即可。
5. 点 **「测试 LLM 连接」**，看到绿色「连接正常」即成功。

**使用 OpenAI 兼容接口的方法**（以 DeepSeek 为例）：

1. 在对应平台申请 API Key。
2. 页面选「OpenAI 兼容接口」，填写：
   - Base URL：`https://api.deepseek.com/v1`
   - API Key：你的 Key
   - 模型：`deepseek-chat`
3. 点「测试 LLM 连接」验证。

### 3.2 选择视频生成方式

| 模式 | 说明 |
| --- | --- |
| **模拟模式（Mock，零成本）** | 默认。用 FFmpeg 生成带文字的占位视频，**无需任何 Key**，用于零成本验证全流程。 |
| **RunningHub（工作流 i2v）** | **真实 API，按次计费**（需 API Key）。用 RunningHub 工作流做**图生视频**：第 1 段首帧由你上传，之后每段用上一段的尾帧做首帧，**逐段确认**后拼接成片，详见 [3.3 用 RunningHub 生成真实视频](#33-用-runninghub-生成真实视频)。 |

> 新手请保持默认「模拟模式」，先完整跑通一次，再考虑接入真实 API。

### 3.3 用 RunningHub 生成真实视频（工作流 i2v）

「RunningHub（工作流 i2v）」是当前版本**已真实接通**的视频能力。选择它后，视频生成统一走 RunningHub **工作流 API 的图生视频**（i2v）：**第 1 段首帧由你手动上传一张图，第 N 段首帧 = 第 N-1 段的尾帧**（FFmpeg 自动截取），严格串行、逐段确认后再拼接成片。

**怎么填（配置区选「RunningHub（工作流 i2v）· 按次计费」后出现）：**

| 输入框 | 填什么 | 说明 |
| --- | --- | --- |
| **API Key** | 你的 RunningHub API Key | **必填**。复用配置区「视频生成」里的 `video_api_key`。 |
| **Base URL** | 留空即可 | 默认国内站 `https://www.runninghub.cn`；国际站填 `https://www.runninghub.ai`。 |
| **工作流 ID** | 留空用默认 `2084067455902765057` | 你已保存并**手动运行过一次**的工作流 ID（见下）。 |
| **实例类型** | `default` / `plus` / `ultra` | 显存档位（24G / 48G / 84G），影响计费单价；留空用 `default`。 |
| **结果保留秒数** | `10`–`180`（默认 `180`） | 生成结果在云端保留的时长；越界会自动钳到 10–180。 |
| **节点参数（8 个）** | 留空用默认 | 首帧/提示词/时长/种子的 `nodeId` 与 `fieldName`，已按实测默认填好，一般无需改。 |

**工作流四步**（程序自动完成，你只需在逐段确认区点「接受」）：

1. **上传首帧** → 取上传返回的 `fileName`（相对路径，不是 URL）；
2. **提交工作流** → `POST /openapi/v2/run/workflow/{工作流ID}`，携带 `nodeInfoList` + `instanceType`；
3. **轮询** → `POST /openapi/v2/query`，直到 `SUCCESS`；
4. **下载** → 立即下载 `results[0].url` 的视频并落盘，再截取尾帧作为下一段首帧。

> **如何拿到工作流 ID**：在 RunningHub 平台把目标工作流**保存并手动运行一次**（否则报 `810`），复制它的 ID 填到「工作流 ID」。
> **节点参数**：工作流的 `nodeId` / `fieldName` 可通过平台 `getJsonApiFormat` 查到；若你的工作流节点与默认不同，改这里即可，**不要**改代码。

填好后点 **「测试视频接口」**：程序会做一次**零成本探针**（只查询一个不存在的任务，**绝不创建真实生成任务、不产生费用**）：

- 未填 Key → 提示「未配置 RunningHub API Key…」；
- 端点地址不对（返回 4xx/5xx）→ 提示「RunningHub 端点返回 HTTP …，请检查 Base URL」；
- Key 无效 / 未授权 → 提示「RunningHub API Key 无效或未授权…」；
- 通过 → 提示「RunningHub 工作流端点可达、鉴权通过」。

**使用 RunningHub 的注意事项：**

- **按次计费**：每生成**一段**视频即产生一次工作流费用。真实出片比 Mock 慢很多（通常数十秒到数分钟/段），程序会**每 5 秒轮询、最长等待 10 分钟**，超时或失败会给中文提示，不卡死。
- **严格串行**：上一段你「接受」后，才提交下一段；同一时刻全局只有 1 个 RunningHub 提交在飞（防止并发超限）。
- **805 失败自动重试一次**（换随机种子）；仍失败则该段标记「失败」，你可以点「重生成本段」。
- **首帧每段重新上传**：不缓存 `fileName`，规避 24 小时过期；尾帧为 **PNG**。
- **费用提醒**：先用 Mock 跑通流程、确认提示词满意后，再切 RunningHub 正式出片。

### 3.4 保存配置

点 **「保存配置」**，配置会写入 `config/config.json`，下次启动自动回填。

### 3.5 人物与场景一致性（提示词锁定卡 + 串行首帧链）

真实出片时，「每个分镜里的人长得不一样、场景也换了」是最常见的问题。当前版本用**两条机制**同时约束一致性：

| 机制 | 界面名 | 作用 | 代价 |
| --- | --- | --- | --- |
| `consistency_lock` | 提示词锁定卡 | 分镜阶段让 LLM 为**每个角色**产出英文「外观锁定卡」（发型/脸型/年龄/服饰/体型等**不随时间变化**的特征），为**每个场景**产出英文「场景锁定卡」（地点/时段/光线/色调/关键陈设），并**逐字注入每一个镜头**的提示词 | 无额外费用 |
| **串行首帧链** | 逐段确认（3.6） | 第 1 段首帧 = 你上传的初始图；第 N 段首帧 = 第 N-1 段视频的**尾帧**，让相邻镜头画面**真正连续** | 无额外费用（已含在视频按次计费里） |

**怎么配合**：先靠「提示词锁定卡」锁住**角色 / 场景**的文字外观；再靠「串行首帧链」锁住**相邻镜头**的实际画面——前一段的尾帧直接成为下一段的首帧，画面自然承接，比纯文字提示词更稳。

**配置键（`config/config.json`）**

```json
{
  "consistency_lock": true
}
```

- 布尔键支持**宽松写法**：`true` / `1` / `"yes"` / `"on"` 都算**开**；`false` / `0` / `"no"` / `"off"` 都算**关**（忽略大小写与首尾空格）。
- `consistency_lock` 默认开启；关闭后走旧逻辑（直接用分镜的英文 `prompt`）。

> 历史版本里的 `chain_continuity` / `anchor_image` / `video_image_endpoint` 与「图像生成」整组配置已随本次架构减法**一并移除**（自建图像生成整体取消，视频统一收敛到工作流 i2v）；`config.json` 里残留的旧键会被程序自动忽略。

### 3.6 逐段确认（串行首帧链）

从脚本就绪后开始，视频生成不再是「后台一次性跑完所有镜头」，而是改成**逐段确认**：每生成一段，就把该段视频与**尾帧**摆出来，你点「接受并继续」后，程序才用这段的尾帧作为下一段首帧继续生成。

**数据流**：

```
初始图(你上传) → 段1: 首帧=初始图 → 生成视频 → 截尾帧(PNG)
                                        ↓ 你点「接受并继续」
       段2: 首帧=段1尾帧 → 生成视频 → 截尾帧
                                        ↓ …
       段N: 首帧=段N-1尾帧 → 生成视频 → 截尾帧 → 全部接受 → 拼接成片
```

**界面（「③.6 逐段确认区」）**：

1. **初始图上传区**：拖拽 / 点击选择一张图（PNG / JPG / WEBP），预览后点「开始生成」；
2. **逐段卡片列表**：每段卡片展示——序号徽标、首帧缩略图（段 1 = 初始图，段 N = 上一段尾帧）、状态徽标（排队 / 生成中 / 待确认 / 已接受 / 失败）、本段视频预览、**尾帧预览**；
3. **操作按钮**：「接受并继续」「重生成本段」（重生成会**自动换随机种子**，可选改提示词）；生成中按钮禁用并显示进度。

**怎么用（推荐流程）**：

1. 等脚本生成完（director 阶段进入「等待上传初始图」）；
2. 在逐段确认区上传初始图 → 点「开始生成」→ 段 1 自动开始；
3. 段 1 生成完出现「待确认」徽标 + 尾帧预览 → 满意点「接受并继续」→ 段 2 自动开始；
4. 重复直到最后一段接受 → 程序自动进入**拼接 + 评估**，产出 `final_video.mp4`；
5. 某段不满意点「重生成本段」→ 该段重新生成（新种子），旧产物被覆盖，段计数不变。

**失败与恢复**：

- 某段 805 失败会**自动重试 1 次**（换随机种子）；仍失败则段标记「失败」并给出原因，你点「重生成本段」即可；
- **断点续跑**：每段结果（视频 / 尾帧 / 首帧来源 / 任务号 / 种子）都持久化到任务目录的 `chain.json`，刷新页面或中断后，重新打开任务即可从当前段继续，不会从头再来。

## 四、跑通全流程

### 第 1 步：输入对话

在「② 输入区」的文本框里粘贴一段**粗糙对话**（就是平时的口语描述，不需要编剧格式）。

不会写？点「载入示例对话」下拉框，选一个示例，再点「填充」即可。

### 第 2 步：设置参数

| 参数 | 可选范围 | 建议 |
| --- | --- | --- |
| 风格 | 写实 / 动漫 / 动画 | 写实 |
| 镜头数 | 2–8 | 4（出片快） |
| 每镜头时长 | 2–10 秒 | 4 秒 |
| 分辨率 | 720p / 1080p | 720p（更快） |

还可勾选「跳过视频评估」以节省 token（仅评估脚本质量）。

**「生成前确认分镜」（默认勾选）**：勾选后，脚本生成完毕会**先停下来**，等你在「③.5 分镜确认区」核对/修改剧情与分镜提示词，确认后才开始生成视频；取消勾选则一路直达出片。想改主意也随时可在输入区切换。

### 第 3 步：开始生成

点 **「开始生成」**，页面「③ 流水线进度区」会依次点亮**五个阶段**：

1. **StoryAgent** —— 粗糙对话 → 完整故事情节（剧情补全，新增）
2. **ScriptAgent** —— 故事情节 → 分镜脚本（分镜提示词）
3. **DirectorAgent（逐段确认）** —— 上传初始图后逐段生成视频（每段「接受并继续」才推进下一段，见 [3.6 逐段确认](#36-逐段确认串行首帧链)）
4. **视频拼接（FFmpeg）** —— 全部接受后合成 `final_video.mp4`
5. **CriticAgent** —— 质量评估

下方「实时日志」会不断刷新当前进度。Mock 模式通常 30 秒内即可完成。

> **若勾选了「生成前确认分镜」**：进度会在第 2 阶段后停住，并出现 **「③.5 分镜确认区」**（此时**尚未生成任何视频**）。请按 [六、分镜确认](#六分镜确认) 核对后点「确认并生成视频」（或在输入区取消勾选，直接出片）。
>
> **若不勾选**：脚本生成完会直接进入 director 阶段「等待上传初始图」——请到「③.6 逐段确认区」上传初始图开始逐段生成。

### 第 4 步：查看剧情与成片

- 点进度区右侧的 **「查看剧情」** 可查看补全后的完整故事情节（`story.json`），并可下载。
- 成片会自动出现在「④ 视频剪辑区」右侧的「原始成片」播放器中，可点 **「下载成片」** 保存到本地。
- 下方「分镜明细」可逐个播放 / 下载单镜头；若某段失败，可在「逐段确认区」点该段的 **「重生成本段」**，不影响其他段。

### 第 5 步：剪辑与导出

详见 [七、视频剪辑](#七视频剪辑)：在「④ 视频剪辑区」的时间轴上**拖拽排序、拖两端手柄裁剪、一刀两段**，实时预览后「导出成片」。你的剪辑方案会**自动保存**，刷新页面也不会丢。

### 第 6 步：查看评估报告

「⑤ 评估报告区」会展示：

- **脚本质量**（4 维度）：连贯性 / 可拍性 / 角色一致性 / 剧情完整度，各 1–10 分；
- **视频保真度**（3 维度）：画面一致性 / 对白匹配 / 风格符合度；
- 总分与评语；可点「下载评估 JSON」。

### 产物在哪里？

每次任务都会在 `outputs/<时间戳>/` 下生成独立目录：

```
outputs/20260210_153000/
├── story.json               # 补全后的完整故事情节（StoryDocument）
├── script.json              # 分镜脚本（shots[].prompt 即分镜提示词）
├── chain.json               # 串行首帧链状态（逐段确认进度 / 断点续跑）
├── frames/initial_frame.png # 你上传的初始图（段 1 首帧）
├── frames/tail_001.png ...  # 每段视频的尾帧（作为下一段首帧）
├── shots/segment_001.mp4 ...# 逐段视频
├── final_video.mp4          # 拼接成片（原始成片，剪辑导出不会覆盖它）
├── evaluation_report.json   # 评估报告
├── edit_plan_draft.json     # 剪辑草稿（自动保存，用于刷新/换设备后恢复）
└── exports/                 # 剪辑导出（每次导出配对生成，绝不覆盖）
    ├── export_20260210_153500.mp4        # 导出的新成片
    └── edit_plan_20260210_153500.json    # 与成片同一时间戳的剪辑方案（可复现）
```

> `edit_plan_draft.json` 是**工作草稿**（随时被最新剪辑覆盖）；`exports/edit_plan_*.json` 是**导出留档**（每次导出独立成对，永不覆盖）。两者用途不同，互不影响。

## 五、剧情补全

**一句话：** 你只需输入一段粗糙对话，StoryForge 会先用大模型把它补全为一个完整、连贯的故事情节，再据此拆解成一个个分镜提示词。

### 5.1 它是怎么工作的

```
粗糙对话 → StoryAgent 补全完整故事（story.json）
         → ScriptAgent 拆解分镜脚本（script.json，shots[].prompt = 分镜提示词）
         → DirectorAgent 逐镜头生成视频
```

- 完整故事情节保存为 `story.json`，字段包含：故事标题、一句话梗概、**完整剧情正文（synopsis）**、时空场景设定、角色表、**情节节点（beats，起承转合）**、题材、主题。
- 「情节节点」是分镜拆解的最小依据，保证分镜覆盖起承转合、剧情连贯。

### 5.2 怎么查看剧情

1. 任务跑完后，点进度区右侧的 **「查看剧情」** 按钮；
2. 弹窗展示一个**可编辑剧情表单**：故事标题、题材、一句话梗概、时空场景设定、完整剧情正文（多行文本框）；
3. 表单下方为**只读预览区**：角色表、情节节点（起承转合）直接展示；原始 `story.json` 全文收在「展开原始 JSON」折叠区里，可核对或下载。

### 5.3 编辑剧情 → 重新生成分镜

改完剧情不用重跑整个流程，可以「就地改、再出分镜」：

1. 在剧情弹窗里直接修改标题 / 题材 / 梗概 / 场景设定 / **剧情正文**；
2. 点弹窗底部的 **「保存并重新生成分镜」**；
3. 系统会**新建一个任务**，把修改后的完整剧情作为输入，从 `script`（分镜拆解）阶段开始重新跑——即**跳过剧情补全**（`story`），命中你手改的剧情直接产出新的分镜提示词，随后照常生成视频；
4. 弹出的确认框会提示「将基于修改后的剧情重新生成分镜」，确认后页面顶部输入框会自动填回原始对话（若为空则回退用标题），保持可追溯。

> 为什么是「新建任务」而不是原地改？——原地改会让已经生成好的视频与新剧情对不上，容易产生「半新半旧」的脏状态。新建任务让旧产物完整保留，你随时能回退对比。
>
> 角色表与情节节点目前是**只读**的（它们由剧情补全阶段生成，手改容易与正文冲突）；如需大改，建议直接改剧情正文后重跑，或回到第 1 步重新输入对话。

### 5.4 剧情补全失败会怎样

若大模型在该阶段输出不合法（JSON 解析失败），系统会自动重试 2 次；仍失败则任务标记为 **失败**，错误信息含「剧情补全失败：…」。此时**不影响**其他已存在的任务与旧接口。

> 提示：剧情补全对模型理解能力要求较高，建议使用 `qwen2.5:14b` 及以上，或商业 API 模型。

## 六、分镜确认

**一句话：** 勾选「生成前确认分镜」后，系统会先把完整剧情与逐镜头分镜提示词摆出来让你**核对 / 修改**，你确认后才开始生成视频——避免「闷头出片、结果不满意」。

### 6.1 什么时候会出现

- 在「② 输入区」勾选 **「生成前确认分镜」**（默认已勾选）；
- 点「开始生成」，等 `StoryAgent` 与 `ScriptAgent` 跑完（进度区第 1、2 阶段变绿）；
- 任务会**挂起**（状态显示「待确认」），页面出现 **「③.5 分镜确认区」**。此时**尚未生成任何视频**。

> 未勾选该开关时不会出现确认区，流程与旧版完全一致（一路直达出片）。

### 6.2 界面构成

- **左侧「完整故事情节」（可编辑）**：标题 / 题材 / 一句话梗概 / 场景设定 / **完整剧情正文（synopsis，核心）**；下方为只读的**角色表**与**情节点**。
- **右侧「分镜提示词（逐镜头可编辑）」**：每个镜头一张卡片，可改 **分镜提示词 prompt / 动作 action / 运镜 camera / 对白 dialogue / 时长 duration**（时长须 2–10 秒）；`shot_id` 为只读标识。
- **底部操作栏**：「跳过确认（按当前分镜生成）」与「✓ 确认并生成视频」。

### 6.3 两种走法

| 你的操作 | 系统行为 |
| --- | --- |
| 改了**完整剧情**后点「确认并生成视频」 | 判定剧情已变更 → **重跑 ScriptAgent**（用新剧情重新拆解分镜），再生成视频 |
| 只改了**分镜提示词**（剧情未动） | **不重跑脚本**，直接采用你手改的分镜，随后生成视频 |
| 什么都没改，直接确认 | 沿用当前脚本，直接生成视频 |
| 点「跳过确认」 | 不做任何修改，按当前分镜直接生成 |

确认后任务在**同一个任务内**继续（`task_id` 不变），进度区接着点亮「分镜视频 → 视频拼接 → 质量评估」。

### 6.4 校验规则（不满足则不会开始生成）

- **完整剧情正文**不能为空；
- 每个镜头的**分镜提示词**不能为空；
- 每个镜头的**时长**须为 **2–10 秒**。

任一项不满足时，按钮上方会给出中文提示，且任务**仍停留在「待确认」**，不会误触发生成——改好再点即可。

> 若刷新页面时任务正处于「待确认」，页面会自动恢复并重新展示确认区，可继续核对/修改。

## 七、视频剪辑

「④ 视频剪辑区」用于把逐镜头生成的片段**像普通剪辑软件一样自由剪辑**成你自己的版本。

### 7.1 界面构成

1. **剪辑预览播放器**：按「启用片段 × 顺序 × 起止时间」播放当前剪辑序列；旁边显示**预计总时长**。
2. **时间轴**：顶部是**秒刻度尺**，下方是**片段轨道**。每个片段块显示序号、`shot_id`（分割后附带 `#1`/`#2` 片段号）与末帧缩略图；片段宽度**正比于**其裁剪后时长（越长的片段越宽）。一条**红色播放头**指示当前位置。
3. **操作栏**：「▶ 播放剪辑」「✂ 在播放头处分割」「重置剪辑」「导出成片」。

### 7.2 常用剪辑操作

| 操作 | 怎么做 | 效果 |
| --- | --- | --- |
| **拖拽排序** | 按住片段块拖到目标位置松开 | 调整片段先后顺序 |
| **双臂裁剪** | 拖动片段块**左侧 / 右侧的手柄** | 调整该段起止（in / out）；起点不得越过终点，越界会自动回退整段 |
| **启用 / 禁用** | 点击片段块左上角的 **✓ / ⊘** | 禁用片段置灰，**不参与**预览与导出 |
| **定位播放头** | 单击**刻度尺或轨道**上的任意位置 | 播放头跳到该处；若落在某片段上，该片段被选中并载入预览 |
| **一刀两段** | 先选中片段、把播放头落到该片段**内部**，再点「✂ 在播放头处分割」 | 该片段拆成两段（如 `shot_001#1`、`shot_001#2`），可各自排序 / 裁剪 / 启停 |
| **实时预览** | 点「▶ 播放剪辑」 | 按当前时间轴顺序播放，**播放头同步走动** |

> 若某片段「原时长」未知（时长探测失败），它仍会显示在时间轴上并按整段处理，只是不可裁剪。

### 7.3 一刀两段（分割）细节

- 分割只在「**已选中某片段** 且 **播放头落在该片段内部**」时可用，端点处按钮为灰色不可点；
- 分割会给两段分别赋予唯一片段号（后缀 `#1` / `#2`），**再次分割**已分割的段会继续追加后缀（如 `#1#1` / `#1#2`），**永不撞号**；
- 两段仍指向同一个源视频，仅在剪辑方案里以不同起止区分，因此**不会重复生成视频**；
- 分割、排序、裁剪、启停都会**自动保存**（见 7.5）。

### 7.4 导出成片

1. 设置好剪辑后，点 **「导出成片」**；
2. 按钮会显示「导出中…」（导出为同步执行，稍候片刻）；
3. 导出成功后，出现导出成片的播放器，以及两个下载按钮：**下载导出成片**、**下载剪辑方案 (edit_plan)**。

**产物命名（重要）**：每次导出都会在 `outputs/<时间戳>/exports/` 下**配对生成两个文件**（同一时间戳），**绝不覆盖**原始 `final_video.mp4`：

- 成片：`exports/export_<YYYYMMDD_HHMMSS>.mp4`
- 方案：`exports/edit_plan_<同一个YYYYMMDD_HHMMSS>.json`（其中每个片段带有 `clip_id`，可精确复现分割）

第 4 步提到的 `final_video.mp4` 全程保持不变，你随时可以在右侧「原始成片」播放器里对比。

### 7.5 刷新后自动恢复剪辑方案

**你的剪辑不会丢。** 每做一次剪辑动作（排序 / 裁剪 / 启用开关 / 分割 / 重置）后约 0.4 秒，系统会自动把当前剪辑方案**保存到服务端**（`outputs/<时间戳>/edit_plan_draft.json`），同时把当前任务 ID 记在浏览器里。

所以：

- **刷新页面 / 关闭标签页再打开**：页面会自动读回任务，恢复进度与**你上次的剪辑方案**（顺序、裁剪、启用状态、分割结果全部还原）；
- **换浏览器 / 清缓存 / 换设备**：只要任务 ID 还在，剪辑方案都在**服务端**，照样能恢复（这也是为什么草稿不放浏览器 localStorage，而放服务端）；
- **重跑同一个任务**：进入时同样会自动套用最近一次草稿。

> 若草稿文件缺失或损坏，系统**静默降级**为原始顺序（不报错、不阻塞），你重新剪一次即可。
>
> **旧版本草稿**（不含片段号 `clip_id`）也完全兼容：会按「每个镜头一段」原样还原。
>
> 若有片段在草稿里没被覆盖到（理论上不会发生），系统会把它们**追加到末尾**，确保不丢片。

### 7.6 重置

点 **「重置剪辑」** 可把顺序 / 裁剪 / 启用恢复到原始状态（即 `final_video` 的原始片段顺序、全启用、无裁剪、无分割）。重置同样会自动写入草稿。

### 7.7 本次不支持的剪辑能力

转场特效、字幕、配乐、多轨时间轴、变速变调、调色/滤镜、画中画**均不支持**（需要引入时间轴引擎与 `filter_complex` 编排，成本高、投入产出比低）。当前版本聚焦「挑镜头、拼顺序、去废片、切一刀」四大核心诉求。

## 八、常见问题

### Q1：双击 start.bat 一闪而过 / 提示找不到 Python

说明 Python 未安装或未加入 PATH。请重新安装 Python，**务必勾选 "Add Python to PATH"**，然后重新双击 `start.bat`。

### Q2：页面顶部出现红色横幅「未检测到 FFmpeg」

说明系统 PATH 中没有 FFmpeg。请按 [1.2 安装 FFmpeg](#12-安装-ffmpeg必需) 配置，**配置后需要重启服务**（关闭黑窗口，重新双击 `start.bat`）。

### Q3：点「测试 LLM 连接」提示「无法连接 localhost:11434」

说明 Ollama 没有运行。请：

1. 打开命令提示符执行 `ollama serve`（保持窗口打开）；
2. 或确认 Ollama 安装后已在后台运行；
3. 或在配置区手动填写正确的 Base URL。

### Q4：生成脚本时报「LLM_BAD_JSON」解析失败

部分小模型输出 JSON 不稳定。程序会自动重试 2 次；若仍失败，请：

- 更换参数更大的模型（如 `qwen2.5:14b` 及以上）；
- 或改用 OpenAI 兼容接口的商业模型。

### Q5：任务失败，提示「没有已接受的片段」或某段生成失败

请检查：

- FFmpeg 是否可用（页面顶部的环境提示）；
- 若使用**真实视频 API**：检查 API Key 与余额是否正确、Base URL 是否可达、工作流 ID 是否已保存并手动运行过一次。目前 **RunningHub（工作流 i2v）已真实接通**（详见 [3.3](#33-用-runninghub-生成真实视频)）。若拿不准，先切回「模拟模式」验证流程；
- 某段失败时，到「逐段确认区」点该段「重生成本段」重试。

### Q6：端口 8000 被占用怎么办？

无需处理。程序会自动使用 8001、8002……，页面顶部会显示实际地址。

### Q7：如何修改视频尺寸 / 镜头数量？

在「② 输入区」直接调整「镜头数」「每镜头时长」「分辨率」下拉框后重新生成即可。

### Q8：生成的视频没有声音？

Mock 模式**默认静音**（这是设计如此）。如需配音，可后续版本支持 BGM/朗读（当前版本未实现）。

### Q9：config.json 里的 API Key 是明文，安全吗？

本应用为本地单机程序，Key 只保存在你自己电脑的 `config/config.json` 中，不会上传到任何服务器。页面读取配置时会脱敏显示（`sk-****abcd`），保存时若你没改动脱敏值，程序会保留原始 Key。

### Q10：如何彻底重装依赖？

删除项目下的 `.venv` 文件夹，重新双击 `start.bat` 即可重新创建并安装。

### Q11：点了「开始生成」却停在「待确认」不动？

这是「生成前确认分镜」在起作用——脚本已经生成，正等你核对。请到 **「③.5 分镜确认区」** 修改并点「确认并生成视频」（或点「跳过确认」）。若不想每次确认，可在「② 输入区」**取消勾选**「生成前确认分镜」。

### Q12：在确认区改了什么，为什么有些改动没生效？

- 改了**完整剧情** → 会**重跑脚本**，此时你对**旧分镜**的手改会被忽略（因为要用新剧情重新拆解）；
- 只改**分镜**（剧情没动）→ 直接采用你的手改，不重跑。
想「以分镜改成分为准」，就**别动左侧剧情**；想「以剧情为准重新拆解」，就改剧情。

### Q13：时间轴上的片段为什么有的宽有的窄？

片段宽度**正比于它裁剪后的时长**，所以裁得越短越窄、越长越宽，方便一眼看出节奏。极端短的片段会保留一个最小宽度以便点选。

### Q14：选了 RunningHub，点「测试视频接口」提示「API Key 无效或未授权」？

说明 Key 不对或没有权限。请：

1. 到 RunningHub 控制台确认 Key 是否复制完整、是否已启用；
2. 确认 Base URL 与站点一致（**国内站 `https://www.runninghub.cn`，国际站 `https://www.runninghub.ai`**）；
3. 重填后再次测试。测试本身**零成本**（只查一个不存在的任务，不会创建真实生成、不产生费用）。

### Q15：RunningHub 生成的相邻镜头画面还是不连贯？

先确认「逐段确认」是否真正生效：每段生成后会出现**尾帧预览**，你点「接受并继续」后，该尾帧才会成为下一段的首帧。若你**跳过了确认**或**每段都重生成**，串行链可能被反复打断。

- 画面仍不连贯 → 确认 `consistency_lock`（提示词锁定卡）是**开**的（见 [3.5](#35-人物与场景一致性提示词锁定卡--串行首帧链)），并尽量**接受**满意的段、少重生成；
- 首帧确实传了但差异大 → 「一张静帧 + 新提示词」无法 100% 锁定外观，属正常上限，可微调该段提示词后重生成。

### Q16：报错 `errorCode=803`（nodeInfoList 节点不匹配）？

这是**工作流节点参数不对**——提交体的 `nodeId` / `fieldName` 与你工作流实际节点不一致。请：

1. 在 RunningHub 平台用 `getJsonApiFormat` 查出正确节点；
2. 把首帧 / 提示词 / 时长 / 种子的 `nodeId` 与 `fieldName` 填到配置区对应输入框（见 [3.3](#33-用-runninghub-生成真实视频)）；
3. 重试。此错误**不会自动重试**，改对节点即可。

### Q17：报错 `errorCode=805`（任务失败）？

805 表示 RunningHub 工作流任务执行失败。程序会**自动换随机种子重试 1 次**；若仍失败，该段会标记「失败」并展示失败原因。此时你可到「逐段确认区」点该段「重生成本段」（可顺带修改提示词）。若反复 805，请检查工作流是否可正常运行、提示词是否合法、余额是否充足。

### Q18：报错 `errorCode=810`（工作流未保存 / 未运行）？

说明该工作流 ID 尚未在平台**保存并手动运行过一次**。请到 RunningHub 平台把目标工作流保存，并**手动运行一次**成功后，再回来重新提交。
