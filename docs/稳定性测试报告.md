## 五、发现的问题与风险

### Q1（提示词强约束相关，**不影响 StoryForge 正常使用**）

**现象**：当提示词**没有强 system 约束**时（例如直接发一句"把剧情拆成3个镜头，只输出JSON"），模型会把**推理过程写进正文**：

```
'\n\n首先，用户要求我作为编剧，把给定的剧情拆成3个镜头的分镜脚本。只输出JSON。
关键点：\n- 需要拆成3个镜头。\n- 每个镜头应该描述一个具体的场景。...'
```

**影响**：① 正文开头混入散文；② 散文消耗 token，可能导致后面的 JSON 被截断（Phase 2 的 5/5 结构校验失败即由此引起，`finish_reason=length`）。

**是否为缺陷**：**否**。这是 Thinking 微调模型的固有行为（模型身份为 `Qwen3 30B A3B Thinking 2507`）。

**StoryForge 是否受影响**：**不受影响**。StoryForge 靠两道防线规避：
1. `app/services/prompt_templates.py` — 强 system 约束（"只输出一个 JSON 对象，不要任何解释"）
2. `app/services/llm_client.py` — 空内容兜底 + JSON 容错解析与重试

实测证据：3 次端到端流水线的脚本生成与评估**全部输出合法 JSON**。

**给调用方的建议**：若在别处直接调用该 LLM 接口，**务必保留强 system 约束并明确要求 JSON 输出**。

### Q2（信息级）

llama-server 为**单模型服务**，请求里的 `model` 字段被忽略 —— 填错模型名**不会报错**，而是照常推理。调用方不应依赖模型名校验。

## 六、已知限制（沿用部署说明）

| 限制 | 说明 |
| --- | --- |
| 大请求并发 | 占满上下文的并发请求会排队；**小请求可并发**（实测 2 路并行正常） |
| 依赖链路 | 需服务器在线 + SSH 隧道保持 |
| 首次加载 | 服务加载模型约 7s（仅服务启动时一次） |
