### 原始需求复述

对标腾讯开源项目 `digitalhuman` 的 **ScriptAgent** 框架（长程对话 → 电影级视频生成的多智能体框架），做一个**带可视化网页界面的本地应用**：

1. **ScriptAgent** —— 把粗糙对话转换为详细的分镜拍摄脚本；
2. **DirectorAgent** —— 把脚本转成多镜头连贯视频，维护镜头间视觉连续性；
3. **CriticAgent** —— 评估脚本质量与视频生成保真度。

要求普通用户无需编程也能跑通整条流水线，**所有模型调用均走 API**（不本地部署大模型）。

## 二、产品定义

### 2.1 核心价值主张

> **一句话**：把「一段随便写的对话」变成「一部有分镜、有视频、有评估报告的小短剧」，全程点点鼠标即可完成。

三个必须成立的价值点：

| 编号 | 价值点 | 说明 |
| --- | --- | --- |
| V1 | **零门槛跑通** | 用户不写一行代码，双击 `start.bat` 就能在浏览器里完成「输入对话 → 拿到成片」。 |
| V2 | **零成本验证** | 未配置任何付费视频 API 时，**Mock 模式**用 FFmpeg 生成带文字的占位视频，完整跑通全流程，让用户先看到"成品长什么样"。 |
| V3 | **真实 API 可插拔** | 用户填一个 `base_url + api_key` 即可接入真实 LLM；配置视频 API Key 后，同一套流程自动切换为真实出片，**无需改代码**。 |

### 2.2 产品目标（3 个正交目标）

| 目标 | 描述 | 衡量方式 |
| --- | --- | --- |
| **G1 易用性** | 非专业用户 10 分钟内完成首次成片 | 从启动到下载到最终视频，操作步骤 ≤ 6 步，无命令行操作 |
| **G2 可扩展性** | 模型层与业务层解耦，新增模型不改业务代码 | LLM 层支持 ≥ 2 种模式；视频层支持可插拔适配器（Mock / RunningHub 模型 API，注册表 `ADAPTER_REGISTRY` 可扩展） |
| **G3 可验证性** | 全流程可观测、可评估、可复现 | 每个阶段有进度与日志；产出结构化脚本 JSON + 评估报告 JSON |

**明确不做（Out of Scope）**

- 不做用户账号体系、不做多租户与云端部署（纯本地单机应用）。
- 不做模型本地化部署 / 微调 / 训练（全部走 API 或 Ollama）。
- 不做视频特效编辑、剪辑时间线（只做拼接与预览下载）。
- 前端不做复杂打包与工程化（保持轻量，便于交付）。

### 2.3 目标用户与典型场景

| 用户画像 | 特征 | 核心诉求 |
| --- | --- | --- |
| **U1 内容创作者** | 有故事创意，不写代码，想快速出短剧 Demo | 快速把脑内对话变成可视化成片 |
| **U2 产品/研究人员** | 想验证 ScriptAgent 这类多智能体流水线的效果 | 可切换模型/参数、可复现、可看评估指标 |
| **U3 AI 爱好者** | 本地有 Ollama，想零成本试玩 | Mock 视频 + 本地 LLM，完全免费跑通 |

**典型使用场景**

| 场景 | 描述 | 关键路径 |
| --- | --- | --- |
| S1 首次体验（零成本） | 用户下载后直接启动，不配置任何 Key | 启动 → 选 Ollama → 输入对话 → Mock 出片 → 预览下载 |
| S2 真实出片 | 用户已有 DeepSeek / RunningHub 等 API Key | 配置 Key → 输入对话 → 生成脚本 → 真实视频 → 合并成片 |
| S3 质量调优 | 用户对脚本不满意 | 调整"风格/时长/镜头数"参数 → 重新生成 → 查看评估报告对比 |
| S4 研究对比 | 研究人员对比不同 LLM 的脚本质量 | 切换 base_url/model → 批量跑同一段对话 → 导出评估 JSON |

## 三、技术规范

### 3.1 智能体流水线（核心业务流程）

```
┌─────────────────────────────────────────────────────────────────────┐
│                        用户输入（粗糙对话）                          │
│   "小明和小红在咖啡馆相遇，讨论要不要一起创业..."                     │
└───────────────────────────────┬─────────────────────────────────────┘
                                │
                                ▼
┌─────────────────────────────────────────────────────────────────────┐
│ 【阶段 1】ScriptAgent  —— 对话 → 分镜拍摄脚本                        │
│  输入：粗糙对话文本 + 风格 + 镜头数                                  │
│  输出：结构化脚本 JSON（角色描述 / 场景描述 / 角色站位 / 逐条对白）    │
│  依赖：LLM 接口层（OpenAI 兼容 或 Ollama）                           │
└───────────────────────────────┬─────────────────────────────────────┘
                                │  script.json
                                ▼
┌─────────────────────────────────────────────────────────────────────┐
│ 【阶段 2】DirectorAgent —— 脚本 → 多镜头连贯视频                     │
│  2.1 镜头拆解：把脚本切成 N 个镜头（shot_001 ... shot_00N）           │
│  2.2 逐镜头生成：调用视频生成接口层（Mock / RunningHub 模型 API）   │
│  2.3 视觉连续性：从上一个镜头提取末帧，作为下一个镜头的参考帧          │
│  2.4 视频拼接：用 FFmpeg concat 把所有镜头合成 final_video.mp4        │
│  输出：shots/shot_001.mp4 ... + final_video.mp4                      │
│  依赖：视频生成接口层 + FFmpeg                                        │
└───────────────────────────────┬─────────────────────────────────────┘
                                │  final_video.mp4
                                ▼
┌─────────────────────────────────────────────────────────────────────┐
│ 【阶段 3】CriticAgent —— 质量评估                                    │
│  脚本评估：LLM 主观打分（连贯性 / 可拍性 / 角色一致性 / 剧情完整度）   │
│  视频评估：画面与脚本的一致性打分（LLM 打分 + 可选客观指标）           │
│  输出：evaluation_report.json + 网页可读报告                          │
│  依赖：LLM 接口层（可选多模态）                                       │
└───────────────────────────────┬─────────────────────────────────────┘
                                ▼
                   结果预览 + 下载 + 评估报告
```

### 3.2 关键抽象层设计（约束落实）

#### 3.2.1 LLM 接口层 —— 双模式

| 模式 | 配置项 | 兼容目标 | 默认值 |
| --- | --- | --- | --- |
| **模式 A：OpenAI 兼容接口** | `base_url`、`api_key`、`model` | DeepSeek、通义千问、智谱 GLM、Kimi(Moonshot)、OpenAI 等 | `base_url=https://api.deepseek.com/v1`，`model=deepseek-chat` |
| **模式 B：本地 Ollama** | `base_url`、`model`（无需 api_key） | Ollama 任意本地模型 | `base_url=http://localhost:11434`，`model=qwen2.5:14b` |

**要求**

- 界面上通过**单选/开关**自由切换两种模式，配置项随模式动态变化（Ollama 模式隐藏 api_key 输入框）。
- 提供**「测试连接」按钮**，返回连通性、可用模型列表、延迟。
- 必须有**连通性校验与友好错误提示**（Key 错误 / 模型不存在 / 网络不通 / Ollama 未启动）。
- 统一封装为一个 `LLMClient`（`chat(messages, **kwargs) -> str`），上层智能体不感知底层差异。

#### 3.2.2 视频生成接口层 —— 统一适配器 + Mock 必装

```
                    ┌──────────────────────────────┐
   业务层调用  ───▶ │  VideoGeneratorInterface     │
                    │  generate(prompt, image_ref, │
                    │    duration, size, style)    │
                    │   -> video_path              │
                    └──────────────┬───────────────┘
                                   │ 按配置路由
                        ┌──────────┴──────────┐
                        ▼                     ▼
                   ┌─────────┐        ┌──────────────────┐
                   │ Mock    │        │ RunningHub       │
                   │ (必装)  │        │ 模型 API(文生视频)│
                   └─────────┘        └──────────────────┘
                     FFmpeg              真实 API
                     占位视频
```

| 适配器 | 优先级 | 说明 |
| --- | --- | --- |
| **Mock（模拟模式）** | **P0 必装** | 无需网络与 Key。用 FFmpeg 生成 **带文字的色块/渐变视频**，画面中包含镜头序号、场景描述、对白文本，时长与分辨率可配置。**保证零成本跑通全流程。** |
| **RunningHub（模型 API）** | P0（真实可选） | 真实 API，通过配置 `api_key`（需「企业级-共享」Key）启用；**文生视频**（不支持首帧参考图）。 |

**Mock 生成的占位视频要求**

- 使用 FFmpeg `lavfi` 滤镜生成纯色/渐变色背景，叠加文字（镜头编号 + 场景 + 对白）。
- 视频参数：默认 `1280x720`，`24fps`，每镜头 `4s`（可配置）。
- 输出必须与真实适配器**格式一致**（`mp4 / H.264`），确保后续拼接环节完全无差异。

### 3.3 需求池（Requirements Pool）

#### P0 —— 必须实现（Must Have）

| ID | 需求 | 说明 | 验收要点 |
| --- | --- | --- | --- |
| **P0-1** | **配置管理** | 网页上配置 LLM 模式（OpenAI 兼容 / Ollama）与视频生成模式（Mock / 真实 API）；配置持久化到本地文件（如 `config.json`），下次启动自动回填 | 两种 LLM 模式均可保存并生效；配置项非法时有提示 |
| **P0-2** | **连接测试** | 「测试 LLM 连接」「测试视频接口」按钮 | 返回成功/失败与原因，3s 内给出结果 |
| **P0-3** | **对话输入** | 文本框输入粗糙对话；提供 ≥ 2 个内置示例对话（一键填充）；可设置风格、镜头数、每镜头时长 | 空输入有校验提示；示例可一键填入 |
| **P0-4** | **脚本生成（ScriptAgent）** | 调用 LLM 把对话转成分镜脚本，输出结构化 JSON，并在页面展示（角色/场景/站位/对白） | JSON 结构合法、可折叠查看；支持手动重新生成 |
| **P0-5** | **分镜视频生成（DirectorAgent + Mock）** | 按镜头逐个生成视频；**Mock 模式必须可用**；展示每个镜头的生成状态（等待/生成中/完成/失败） | Mock 模式下 N 个镜头全部产出 `mp4` 文件 |
| **P0-6** | **视觉连续性** | 从上一镜头提取末帧作为下一镜头的参考帧（Mock 模式下用 FFmpeg 抽帧实现，真实模式传入参考图） | 有抽帧产物落盘，可查看 |
| **P0-7** | **视频拼接** | 用 FFmpeg 把所有镜头按顺序拼接为 `final_video.mp4` | 成片时长 ≈ 各镜头时长之和；可在网页内播放 |
| **P0-8** | **结果预览与下载** | 网页内嵌播放器预览每个镜头与最终成片；提供下载按钮（单镜头 / 成片） | 视频可播放、可下载 |
| **P0-9** | **评估报告（CriticAgent）** | 对脚本与成片打分，页面展示可视化报告（分数 + 维度 + 评语） | 报告含脚本维度分与视频一致性分，可下载 JSON |
| **P0-10** | **一键启动** | `start.bat` 双击启动：检查 Python 依赖 → 启动 FastAPI → 自动打开默认浏览器 | 无命令行知识也能启动；端口被占用时有提示 |
| **P0-11** | **中文使用说明** | 面向非专业用户的说明文档（含截图位说明、常见问题） | 覆盖安装、启动、配置、跑通、排错 |
| **P0-12** | **全流程进度可视化** | 页面展示流水线各阶段状态与实时日志 | 用户能看出当前卡在哪一步 |
| **P0-13** | **失败与错误处理** | 单个镜头失败不阻断全流程，支持重试该镜头；错误信息可读 | 断网/Key 错误场景下有明确提示 |

#### 用户操作流程（Happy Path）

```
1. 双击 start.bat                     → 终端启动服务，浏览器自动打开 http://127.0.0.1:8000
2. ① 配置区：选择 LLM 模式 + 视频模式  → 点「测试连接」确认绿灯（Mock 模式可跳过视频测试）
3. ② 输入区：粘贴对话 / 点「载入示例」   → 选风格、镜头数、时长
4. 点「🚀 开始生成」                    → ③ 进度区依次点亮四个阶段
5. 等待完成（Mock 模式约 30 秒内）      → ④ 预览区自动播放成片
6. 看 ⑤ 评估报告                       → 不满意可回 ② 调参重生成
7. 点「⬇ 下载成片」                    → 本地得到 final_video.mp4
```

### 3.8.1 决策结论（v1.1）

> 本节为上表 Q1–Q12 的**最终拍板结论**，由 team-lead 于 v1.1 评审确认。**与上表「建议默认值」冲突时，一律以本节为准。**

| 编号 | 最终决策 | 对实现的约束 |
| --- | --- | --- |
| **Q1** | **前端采用原生 HTML + 自写 CSS + 原生 JS，零外部 CDN 依赖**（不使用 Vue CDN，也不使用 Tailwind CDN）。**原「建议 ② CDN Vue 3」作废。** 理由：本地应用必须保证**离线可用与启动可靠性**，避免 CDN 加载失败导致界面白屏。 | 前端不得引用任何外网资源（无 `<script src="https://...">`、无 Google Fonts、无 CDN 图标库）；图标用 Unicode/内联 SVG；样式全部写在自维护的 `static/style.css`；不使用任何 npm 构建链。§3.5 界面设计稿布局不变。 |
| **Q2** | 默认端口 **8000**，被占用时**自动 +1** 探测可用端口 | 启动日志与页面上显示实际访问地址；`start.bat` 打开的 URL 必须与后端实际监听端口一致 |
| **Q3** | Mock 视频画面 = **渐变色块 + 文字 + 镜头编号 + 进度条** | FFmpeg 滤镜需实现：渐变背景、叠加镜头编号（如 `SHOT 003 / 006`）、场景与对白文字、底部进度条；保证每个镜头画面可区分 |
| **Q4** | 默认 **4s × 4 镜头**；**镜头数可配 2–8**，**单镜头时长可配 2–10s** | 前端下拉/滑杆取值范围严格限制在 2–8 与 2–10s，越界需校验拦截 |
| **Q5** | 默认 **720p**，可选 **1080p** | 分辨率枚举仅 `720p / 1080p`；Mock 与真实适配器共用该枚举 |
| **Q6** | Ollama 需**启动时自动探测 11434 端口并列出本地模型** | 探测失败不阻塞应用启动，仅在配置区提示「未检测到 Ollama」并提供"手动填写"入口 |
| **Q7** | 评估维度：**脚本 4 维度**（连贯性 / 可拍性 / 角色一致性 / 剧情完整度）+ **视频 3 维度**（画面一致性 / 对白匹配 / 风格符合度），**1–10 分** | 报告固定 4+3 个维度；脚本分与视频分各算总分；各维度需附一句评语 |
| **Q8** | 评估**真调用 LLM**；Mock 视频模式下提供**「跳过视频评估」复选框** | 勾选后仅评估脚本，报告中视频部分标记为「已跳过」；未勾选时视频三维度照常打分 |
| **Q9** | 音轨**默认静音** | Mock 视频无音轨；真实适配器若返回带音视频则保留原音轨，不做混音 |
| **Q10** | api_key **明文存 `config/config.json`**，**页面读取时脱敏** | 存储不做加密；`GET /api/config` 返回 `sk-****abcd` 形式；保存时若用户未修改脱敏值则保留原值 |
| **Q11** | **`docs/使用说明.md` + 页面内「帮助」弹窗，两者都要** | 说明文档面向非专业用户，覆盖安装/启动/配置/跑通/常见问题；页面右上角「帮助」按钮打开弹窗，内容为文档精简版 |
| **Q12** | **需要真机验证**：在 Windows 本机实测 FFmpeg 全流程 | 交付前必须在本机（`E:\ai\storyforge`）跑通一次完整 Mock 流水线：启动 → 生成 → 拼接 → 预览 → 下载 → 评估，并留存产物作为验收证据 |

- §一 项目信息表中「前端技术栈」一行已按 Q1 更新为「原生 HTML + 自写 CSS + 原生 JS，零外部 CDN 依赖」。

### 3.9 风险与应对

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 用户无 FFmpeg 或未加入 PATH | 全流程不可用 | 启动时检测 `ffmpeg -version`，缺失则给出明确安装指引（含下载链接） |
| 真实视频 API 计费高 / 限流 | 用户成本超预期 | 默认 Mock 模式；切换真实 API 前弹窗二次确认并提示预计消耗 |
| 长镜头导致总生成时间长 | 用户体验差 | 分镜头并行/顺序可控；实时进度与日志；支持单镜头重试 |
| 不同 LLM 的 JSON 输出不稳定 | 剧本解析失败 | 提示词强约束 JSON + 解析失败自动重试 + 容错解析（提取代码块/最大括号匹配） |
| Windows 中文路径/编码问题 | FFmpeg 与文件读写报错 | 统一使用 `utf-8`，路径全部由 Python 拼接并加引号传入 FFmpeg |
| 端口 8000 被占用 | 启动失败 | 自动探测可用端口并告知用户实际地址 |

## 五、附录

### 5.1 术语表

| 术语 | 说明 |
| --- | --- |
| ScriptAgent | 把粗糙对话转为详细分镜拍摄脚本的智能体 |
| DirectorAgent | 把脚本转为多镜头连贯视频的智能体 |
| CriticAgent | 评估脚本质量与视频保真度的智能体 |
| Mock 模式 | 用 FFmpeg 生成占位视频，零成本验证全流程 |
| 视觉连续性 | 相邻镜头之间的画面风格/角色/场景保持一致 |
| 适配器（Adapter） | 屏蔽不同视频 API 差异的统一封装 |
