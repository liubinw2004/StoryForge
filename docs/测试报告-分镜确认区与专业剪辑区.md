## 3. 七条证伪方向：逐条尝试与结果

> 每条均「主动构造最可能暴露缺陷的输入」，看实现是否被证伪。结论：**7/7 未被证伪**。

### ① `confirm_script` 原子性 / 幂等（真并发连点）— 未证伪

- 手法：`review=true` 挂起后，起 **8 个线程**用 `threading.Event` 同时 `confirm_script`；
  `DirectorAgent` 替换为带计数锁 `CountingDirector`（`run` 内 `sleep(0.1)` 拉长重叠窗口）。
- 实测：**`ok == 1` 恰好 1 个**，其余 **7 个**稳定抛 `TASK_STATE_INVALID`，
  `CountingDirector` 只被调用 **1 次**，最终状态 `success`。
- 补充：success 之后再确认 → 仍 `TASK_STATE_INVALID`（幂等，不再起线程）。
- 依据实现：`confirm_script` 在**同一把锁内**完成「状态校验 + 迁移 `RUNNING`」，
  线程在**锁外**启动 → 天然串行化。**未发现竞态窗口。**

### ② 校验失败不脏化（`duration=1/30`、空 `prompt`）— 未证伪

- 手法：挂起后提交非法 `ScriptDocument`；对 `script.json` 取 `read_bytes()` 哨兵，
  并对比内存 `get_script().model_dump()`。
- 实测：抛 `CFG_INVALID`；**`script.json` 字节完全不变**；内存脚本不变；
  任务状态**仍 `awaiting_review`**；`director` 阶段**仍 `pending`（未起续跑线程）**。
- 空/纯空白 `prompt`（`"   "`）同上。**校验严格先于落盘与状态迁移，未证伪。**

### ③ 旧草稿兼容（手写无 `clip_id`）— 未证伪

- 手法：手写 3 条**不含 `clip_id`** 的 `edit_plan_draft.json`（含 `end=null`、`enabled=false`）。
- 实测：`GET /edit-plan` **原样解析**（顺序/起止/启停/order 一致），且 **不注入 `clip_id`**；
  原样 `PUT` 回环后再次 `GET`，`(shot_id, enabled, start, end, order)` 投影**逐字一致**。
- 契约层：`ClipEdit` 不带 `clip_id` 时默认 `None`（缺省=旧行为）。**未证伪。**

### ④ split 端到端（真实 FFmpeg 裁剪+拼接）— 未证伪

- 手法：2s mock 源视频，同 `shot_001` 拆两段。
- 实测：
  - 两段 `[0,1]+[1,2]` 导出**实测时长 ≈ 2.0s**（`probe_duration`，`±0.3`），`plan` 含两段 `clip_id`；
  - **无幽灵基础段**（`plan` 中无 `clip_id is None` 的冗段）；
  - `#2` 前置 + 禁用 `#1` → 仅导出 `#2`（顺序/启停**互不影响**）；
  - `start==end`（0 时长）→ **回退整段**（1 条、≈2.0s，不丢片）；
  - 全禁用 → `SYS_BAD_REQUEST`。
- **未证伪**（`covered_shot_ids` 在 `enabled` 判断之前登记，正是消除幽灵段的关键）。

### ⑤ `awaiting_review` 语义 — 未证伪

- 实测：`set_state(AWAITING_REVIEW)` **不写 `finished_at`**（保持 `0.0`）；
  对照组 `SUCCESS` 正常写；`RUNNING/AWAITING_REVIEW` 均 `is_terminal == false`。
- 挂起后连续观察 ~0.4s（20 轮）：状态**恒为 `awaiting_review`**、`director` 恒 `pending`、`shots` 恒 `[]`、`finished_at` 恒 `0.0`，**无自动推进/超时**。
- HTTP `/status` 在挂起时返回 **200 且 `ok == true`**，`state == "awaiting_review"`。**未证伪。**

### ⑥ 回归真实性（214 全绿是否靠删改既有断言）— 未证伪

- 手法：对既有测试文件**清点类名/方法名**并与上一批报告《测试报告-剧情补全与视频剪辑.md》的记录逐条比对。
- 实测：
  - `test_clip_normalize.py`：`TestNormalizeClipsBoundaries` **15 条原样保留**、
    `TestExportEditPlanErrors` **4 条原样保留**、`TestExportIntegration` 原 2 条保留 + 新增 1 条；
    文件从 **21 → 28**（只增不减），新增 `TestNormalizeClipsSplit`（6）。
  - `test_frontend_consistency.py`：原 **4 条全部保留** + 新增 3（**4 → 7**）。
  - `test_confirm_script.py`（16）、`test_edit_draft_api.py`（19）为本批**新增**文件。
- 基线单调递增：**169（上一批）→ 214（本批前）→ 243（含本报告）**。
- **未发现任何删改/弱化既有断言的证据。回归真实。**

### ⑦ 前端接线真实性（新 id 是否真接线）— 未证伪

- 手法：静态解析 `index.html` / `app.js`，断言「id 存在」之外的**真实接线**。
- 实测：
  - `#reviewToggle` 默认 `checked`，且 `review: !!$("reviewToggle").checked` **真正参与 `/run` payload**；
  - `$("splitClipBtn").addEventListener("click", splitClip)` 存在；
  - 确认按钮接 `confirmReview` / `skipReview`，且 JS 中出现真实端点字符串 `/confirm-script"`；
  - split 追加 `parentId + "#1"` / `"#2"`，`parentId = effectiveId(clip)`（多次分割永不撞号）；
  - 轮询识别 `state === "awaiting_review"` → 进入 `enterReviewMode` 且**继续 `startPolling`**（非当终态停轮询）。
- **未证伪**（非「只存在 id」）。
